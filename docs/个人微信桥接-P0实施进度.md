# 个人微信桥接 P0 实施进度

> 依据：`docs/个人微信读取-中台-定向回复链路.md`
> 日期：2026-09-10
> 状态：代码已落地，默认演练模式，等待真实草稿联调

## 1. 已完成

### 中台

- 新增 `POST /api/v1/personal-wechat/events`，接收本地微信事件。
- 新增 `GET /api/v1/personal-wechat/tasks`，认领待发送任务。
- 新增 `POST /api/v1/personal-wechat/tasks/{task_id}/ack`，回传草稿、发送或失败结果。
- 消息写入现有统一会话表 `channel_sessions` 和 `channel_messages`。
- 回复由现有销售 Agent、知识库和客户画像链路生成。
- 同一会话的恢复生成使用串行锁，避免上下文乱序。
- 新增持久化任务表 `personal_wechat_reply_tasks`。

### 本地桥接

- 新增 `wechat_bridge` 模块。
- 复用 `wechat-info-capture` 读取本机微信。
- 支持联系人和群聊白名单。
- 支持消息指纹去重和本地任务去重。
- 支持 `off`、`draft`、`auto`、`manual` 模式配置。
- 默认演练，不操作微信。
- `--live-draft` 才会写入微信输入框。
- 自动发送默认关闭，并有全局二次开关。
- 发送前通过截图模板定位搜索，并对顶部会话标题做 OCR 校验。
- 本地审计写入 `wechat_bridge/data/audit.jsonl`。

## 2. 已验证

- 中台事件接收、AI 任务生成、任务认领、回执和事件幂等测试通过。
- 白名单标准化、自消息过滤和媒体过滤测试通过。
- 本地消息与任务去重测试通过。
- 本机微信读取工具自检通过。
- 已识别本机微信账号和目标联系人“测试客户”的 username。

## 3. 当前安全状态

- `wechat_bridge/config.json` 中 `dry_run=true`。
- `auto_send_enabled=false`。
- 目标“测试客户”已加入白名单，模式为 `draft`。
- 当前运行不会写入微信输入框，也不会发送消息。

## 4. 下一步

1. 启动销售智能体 API。
2. 使用 `python -m wechat_bridge.run --check` 验证中台和微信读取。
3. 使用 `python -m wechat_bridge.run --once` 做演练。
4. 确认任务内容后，使用 `--live-draft` 做真实草稿验证。
5. 草稿连续验证 30 到 50 次后，再决定是否开放白名单联系人自动发送。
