# 商用化加固实施记录

> 日期：2026-09-15  
> 迁移版本：`0010_commercial_hardening`  
> 客户端版本：`1.0.11`  
> 桥接版本：`2026.09.15.1`

## 一、实施顺序

1. 建立租户数据模型和兼容迁移。
2. 接入请求级租户上下文和自动 ORM 过滤。
3. 建立 RBAC、服务账号和 API Key 生命周期。
4. 改造租户级知识库和 pgvector 后端。
5. 改造合规授权、删除、保留期和审计。
6. 增加发布校验、CI、签名校验和部署升级脚本。
7. 同步桌面端和 Web 控制台权限与运维入口。
8. 执行完整质量门和桌面端构建。

## 二、多租户隔离

- 新增 `core/tenancy.py`，统一解析租户和生成租户会话键。
- 新增 `core/tenant_context.py`，通过 ContextVar 和 SQLAlchemy 事件实现请求级自动过滤。
- `0010_commercial_hardening` 为业务表补齐 `tenant_id` 和租户索引。
- 新建客户、线索、任务等对象时，`before_flush` 自动写入当前租户。
- 超管必须显式使用跨租户上下文，普通请求默认只访问本租户。
- 新增多租户自动过滤和 API 隔离测试。

## 三、权限体系

- 新增 `core/rbac.py`，定义角色权限、动作级权限和服务账号。
- 新增 `api_key_accounts` 表，API Key 只保存 SHA-256 哈希。
- 支持服务账号创建、列出、吊销和一次性返回明文密钥。
- 新增 `permission_required()` 和路径级权限中间件。
- API Key 不再默认视为管理员。
- 前端登录后通过 `/api/v1/accounts/me` 读取真实角色和权限，再控制管理菜单和导出按钮。

## 四、RAG 知识库

- 新增 `knowledge_documents`、`knowledge_chunks`、`knowledge_index_versions`。
- 文档、切片、向量、索引版本和检索全部带租户。
- `RAG_BACKEND=auto` 时，PostgreSQL 有 pgvector 扩展则使用数据库向量，否则回退租户 JSON 索引。
- Docker Compose 的 PostgreSQL 镜像改为 `pgvector/pgvector:pg16`。
- 检索先过滤租户、版本和审批状态，再执行向量检索。
- 知识缺口记录增加租户隔离。

## 五、部署升级

- 新增 `scripts/verify_release.py`，校验客户端版本、桥接版本、迁移头和安装包哈希。
- 新增 GitHub Actions CI，覆盖质量门、桌面构建和可选签名校验。
- 新增 `deploy/install_commercial_hardening_20260915.sh`。
- 数据备份包含租户向量索引和知识文件。
- 恢复脚本支持租户向量索引和知识文件。
- Windows 签名未配置证书时会明确标记为未签名，正式发布需配置 CSC 证书。

## 六、测试与合规

- 新增 `tests/test_commercial_hardening.py`。
- 覆盖租户自动过滤、API 越权、服务账号、吊销、RAG 隔离、合规删除、支付验签和版本一致性。
- 删除流程覆盖客户主表、聊天、通知、关注任务以及其余带租户关联字段的 ORM 表。
- 新增保留期清理任务 `tasks.purge_expired_privacy`。
- 审计详情自动脱敏手机号、邮箱和 wxid。
- 桌面端和 Web 控制台增加数据保留状态、到期清理和发布状态检查入口。
