# 中台前端与历史数据同步到服务器

## 一、当前情况

本地已经完成：

- 中台侧边栏按 PRD 分层。
- 中台 UI 样式优化。
- 系统管理做成管理员专属入口。
- 网页端和桌面端渲染文件已同步。

服务器当前 SSH 未配置免密登录，所以不能从本地直接上传。请按下面步骤手动上传一次同步包。

## 二、需要上传的文件

同步包已经生成在本地：

`C:\Users\1\Documents\销售客服智能体\release\sales-agent-ui-data-sync-20260908.zip`

上传到服务器任意目录，建议：

```bash
mkdir -p /opt/sales-agent/sync-20260908
cd /opt/sales-agent/sync-20260908
# 把 zip 传到当前目录后解压
unzip -o sales-agent-ui-data-sync-20260908.zip -d /opt/sales-agent/sync-20260908
```

如果已经有旧目录，先备份：

```bash
mv /opt/sales-agent/sync-20260908 /opt/sales-agent/sync-20260908.old.$(date +%Y%m%d-%H%M%S)
```

## 三、执行同步

```bash
cd /opt/sales-agent
bash /opt/sales-agent/sync-20260908/sync_ui_data_20260908.sh /opt/sales-agent/sync-20260908
```

如果想把这个同步脚本长期保留到项目里，也可以先复制一次：

```bash
cp /opt/sales-agent/sync-20260908/sync_ui_data_20260908.sh /opt/sales-agent/deploy/sync_ui_data_20260908.sh
```

脚本会自动执行：

1. 备份服务器 `.env`、`data/`、`vector_store/`。
2. 复制新的 `static/console.html`、`solda.js`、`solda-enterprise.js`、`vision_console.html`。
3. 复制本地历史数据库和知识库文件。
4. 重建容器并启动。
5. 把 SQLite 历史数据迁移到 PostgreSQL。
6. 重建知识库索引。
7. 检查容器和 `/health`。

## 四、验证

1. 打开：

   `https://your-domain.example/static/console.html`

2. 用中台 API Key 登录，确认：
   - 左侧菜单已经分层。
   - 系统管理入口出现。
   - 客户、线索、订单等页面能显示历史数据。
   - 没有英文模块、空页面或 JSON 报错。

3. 如果普通账号登录：
   - 不应看到系统管理。
   - 手动进入系统管理地址时应被拦截。

## 五、回滚

如果同步后发现异常：

```bash
cd /opt/sales-agent
docker compose down
# 恢复备份
cp .env.bak.<时间> .env
tar -xzf data.bak.<时间>.tar.gz
tar -xzf vector_store.bak.<时间>.tar.gz
docker compose up -d --build
```

## 六、登录凭证

同步包不包含服务器 `.env`，不会覆盖服务器现有 API Key、企业微信 Secret 等配置。数据文件只覆盖业务数据文件，不会修改服务器环境变量。
