# 个人微信读取 + 中台智能体 + 定向回复链路

> 目标：用 `wechat-info-capture` 读取个人微信消息，同步到销售智能体中台，由中台生成回复，再通过本机 UI 自动化定向回复目标用户。
> 原则：读取和发送分离；发送前确认目标；默认草稿模式；所有操作可审计。

---

## 1. 最终链路

```text
个人微信 PC 客户端
  ↓
wechat-info-capture 定时读取本地消息
  ↓
本地桥接服务清洗、去重、识别目标
  ↓
同步到销售智能体中台
  ↓
中台统一会话 + 客户画像 + 知识库 RAG
  ↓
销售智能体生成回复
  ↓
中台返回回复任务
  ↓
本地 UI 回复器搜索目标会话
  ↓
确认当前会话是目标用户
  ↓
草稿模式 / 全自动模式发送
  ↓
发送结果回传中台
  ↓
审计与状态更新
```

---

## 2. 组件划分

### 2.1 本地读取组件

复用 `wechat-info-capture`：

```bash
python capture.py unread
python capture.py sessions
python capture.py capture "目标名称" --hours 1
python capture.py locate "目标名称"
```

职责：

- 读取本机微信消息。
- 返回联系人、群、消息、时间、发送者。
- 不做回复、不改微信数据。

### 2.2 本地桥接服务

新增 `wechat_bridge`：

- 定时轮询未读和指定会话。
- 过滤公众号、系统消息、无关群。
- 按白名单过滤。
- 做消息去重。
- 调用中台消息接收接口。
- 拉取中台回复任务。
- 调用本地 UI 回复器。
- 回传发送结果。

### 2.3 中台销售智能体

现有中台负责：

- 接收统一消息事件。
- 建立或复用统一会话。
- 关联客户、线索、画像。
- 调用销售 Agent、RAG、知识库。
- 生成回复内容。
- 判断是否转人工。
- 生成发送任务。
- 记录审计。

### 2.4 本地 UI 回复器

复用已经验证的桌面自动化思路：

- 使用截图模板定位搜索图标。
- 打开微信搜索。
- 输入目标用户名称。
- 打开对应会话。
- 发送前确认当前会话标题是目标用户。
- 写入回复内容。
- 草稿模式或自动发送。
- 回传结果。

## 3. 中台接口设计

### 3.1 接收本地消息

```http
POST /api/v1/personal-wechat/events
X-API-Key: <key>
```

```json
{
  "tenant_id": 1,
  "account_id": "wxid_xxx",
  "channel": "personal_wechat",
  "target_type": "contact",
  "target_name": "测试客户",
  "target_username": "wxid_customer_example",
  "sender_name": "测试客户",
  "message_id": "wxid_xxx:1730000000",
  "content": "你好",
  "created_at": 1730000000,
  "is_self": false
}
```

返回：

```json
{
  "ok": true,
  "session_id": 123,
  "deduped": false
}
```

### 3.2 拉取回复任务

```http
GET /api/v1/personal-wechat/tasks?account_id=wxid_xxx
```

```json
{
  "items": [
    {
      "task_id": "task_001",
      "target_name": "测试客户",
      "target_username": "wxid_customer_example",
      "content": "你好，请问你想了解哪方面？",
      "mode": "draft",
      "expires_at": "2026-09-10 12:00:00"
    }
  ]
}
```

### 3.3 回传发送结果

```http
POST /api/v1/personal-wechat/tasks/{task_id}/ack
```

```json
{
  "ok": true,
  "status": "sent",
  "sent_at": "2026-09-10 11:30:00",
  "error": ""
}
```

## 4. 自动化设置

按联系人、按群配置：

```text
target_type：contact / group
target_name：测试客户
mode：off / draft / auto
enabled：true
daily_limit：30
hourly_limit：10
min_reply_delay：3
max_reply_delay：8
handover_keywords：人工,投诉,转人工
require_mention：群里是否只回复 @
```

含义：

- `off`：不处理。
- `draft`：AI 生成内容，填入输入框，等人工确认。
- `auto`：AI 生成内容后自动发送。
- `manual`：只提示人工回复。
- `require_mention`：群聊只回复被 @ 的消息。

## 5. 目标确认机制

这是定向回复的安全关键。

发送前必须确认：

```text
1. 目标名称和 username 一致。
2. 搜索结果是精确匹配。
3. 打开会话后，顶部会话标题与目标名称一致。
4. 如果不一致，停止发送，转人工。
```

在 UI 自动化中，可以组合：

- 搜索模板定位搜索图标。
- 搜索结果 OCR 或截图确认。
- 聊天窗口顶部名称 OCR 确认。
- 发送前写入草稿，截图确认。

## 6. 半自动与全自动模式

### 草稿模式

```text
读取消息
→ 中台生成回复
→ 本地打开目标会话
→ 填入输入框
→ 不发送
→ 人工确认
```

### 自动模式

```text
读取消息
→ 中台生成回复
→ 本地打开目标会话
→ 确认目标
→ 自动发送
→ 回传结果
```

建议先跑草稿模式，积累 30 到 50 次无误后，才对白名单联系人开启自动模式。

## 9. 风险控制

- 不发非白名单联系人。
- 不在群聊中自动回复所有消息。
- 发送前必须确认目标会话。
- 默认草稿模式，自动模式需要管理员授权。
- 频率限制、超时熔断、连续失败熔断。
- 所有发送记录写入审计。
- 微信版本升级后重新校验模板和坐标。
