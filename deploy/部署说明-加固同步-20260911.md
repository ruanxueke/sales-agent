> 本包对应本地完成的三阶段优化。**不含** `.env`、`server.env`、数据库、向量库、
> 日志与历史 release 产物；服务器上的 `.env` 不会被覆盖。

## 一、上传并解压

把 `sales-agent-hardening-20260911.zip` 上传到服务器，然后：

```bash
cd /opt/sales-agent
# 先备份现有目录（可选但建议）
tar -czf /opt/sales-agent-backup-$(date +%Y%m%d-%H%M%S).tar.gz \
  --exclude=./data --exclude=./vector_store --exclude=./release .
# 解压覆盖（-o 覆盖同名文件；data/、vector_store/、.env 不受影响）
unzip -o /path/to/sales-agent-hardening-20260911.zip -d /opt/sales-agent
chmod +x /opt/sales-agent/deploy/*.sh
```

## 二、一键执行

```bash
cd /opt/sales-agent
bash deploy/install_hardening_20260911.sh
```

脚本会按 10 步顺序执行，任何一步失败都会**立即中止**并打印回滚命令：

1. 前置检查（docker / compose / `.env` 是否在）
2. 备份到 **`/opt/sales-agent-backups/<时间戳>/`**（`/opt/sales-agent` 之外，避免备份里的 `.env` 被下一次镜像构建打进镜像），并尝试 `pg_dump`
3. 校对 `.env`：**只补缺失项，不覆盖已有值**（`REDIS_PASSWORD`、`PG_PASSWORD`、
   `APP_UID/GID`、`WECOM_ALLOW_PLAINTEXT_CALLBACK=false`、`AUTO_CREATE_TABLES=false`）
4. `chown` `data/` 与 `vector_store/` 到 `APP_UID:APP_GID`
5. `docker compose build`（此步服务照常运行，**必须重建**，见下）
6. 停 `api/official/worker/beat`（**停机窗口开始**），起 `postgres`/`redis`/`redis-cache` 并等健康
7. `docker compose run --rm migrate` 升级数据库结构（失败即中止）
8. `docker compose up -d` 全量启动（**停机窗口结束**）
9. 冒烟检查：`/health`、`/docs` 必须 404、无 Key 必须 401、`alembic_version`、Redis 是否已要密码
10. 输出回滚命令与备份目录

## 三、为什么这次必须重建镜像

前几次发布用的是 `docker cp` 把代码塞进运行中的容器。本次不能用这种方式：

| 变更 | 为什么 `docker cp` 不够 |
|---|---|
| 容器改非 root 运行（`USER app`） | 这是镜像属性，运行时改不了 |
| 加 `HEALTHCHECK` | 同上 |
| 补 `alembic` 依赖 | `docker cp` 不能装包，迁移会 `No module named alembic` |
| `redis-cache` 新服务、Redis 加密码 + AOF | 需要 `docker compose up` 重建容器 |

## 五、回滚

```bash
cd /opt/sales-agent
BK=$(ls -dt /opt/sales-agent-backups/* | head -n1)
cp -a $BK/.env .env
cp -a $BK/docker-compose.yml docker-compose.yml
cp -a $BK/Dockerfile Dockerfile
docker compose down
cp -a $BK/data/. data/
cp -a $BK/vector_store/. vector_store/
docker compose up -d --build
```

数据库结构回滚（谨慎，确认后再执行）：

```bash
docker compose exec -T postgres psql -U sales -d sales < $BK/postgres.sql
```
